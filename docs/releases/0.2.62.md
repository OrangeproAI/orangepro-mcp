# 0.2.62

Everything since 0.2.61.

## In short

- **A proof says whether the test ran the function.** A test that never calls the changed function is no longer reported as "doesn't catch a break". Each proof attempt ends as caught, ran but missed, never ran ("not exercised"), or can't tell ("reach unknown").
- **Every JavaScript and TypeScript proof changes the function at its exact position.** Declarations, const functions, class and object-literal methods, `name: function` properties and the unnamed default export are changed at their recorded bytes. Nothing searches for a function by name any more, so overloads, a recursive call or a function-typed parameter no longer stop a proof.
- **A proof that cannot start says why, in one line.** No usage text.
- **`opro probe-fault` needs an approved expected behavior.** A "proposed" one runs only with `--allow-proposed-oracle`, and the run records it.
- **Model use is recorded.** Every model call's tokens are in the command's JSON result, in `generation-diagnostics.json` and in `.orangepro/model-usage.json`.
- **`opro generate` makes one suite.** `--compare` adds the prompt-only comparison and its judge.
- **An optional add-on interface** for `@orangepro/mcp-pro`. Without the add-on installed nothing changes.
- **The first run after upgrading is a full run:** the report data format and the proof oracle version changed.

## Proofs say whether the test ran the function

- During the run on the mutated copy, the mutated function first appends one line to a file named by `ORANGEPRO_REACH_FILE`. It works in CommonJS and ESM and from Vitest and Jest worker processes, and it never throws.
- **Four outcomes:**
  - caught;
  - ran but missed ("doesn't catch a break");
  - never ran ("not exercised: this test never runs <function>");
  - can't tell ("reach unknown").
- JavaScript, TypeScript, Python and Go carry the marker. Java proofs read "reach unknown".
- Records written by an earlier version read "reach unknown", never "doesn't catch a break".
- **`opro roast`** lists only "ran but missed" as survivors, and lists "not exercised" and "reach unknown" separately. **`opro doctor --proof`** suggests "possibly an equivalent mutation" only for "ran but missed".
- `opro prove --preview` shows the marker lines: a preview is exactly what a proof runs.

## Every JavaScript and TypeScript proof by exact position

- A proof changes the function at its exact position. The proof script checks three things before it writes: the file's hash, the function's own bytes, and the name the function is declared under. Any difference is a refusal that names it. Nothing falls back to a search by name, and OrangePro's own commands cannot reach one.
- **Now proved, no longer refused:** an object-literal property written `name: function` or `name: (…) =>`, a method with a quoted key, and the unnamed default export.
- **Still refused, with the reason:**
  - an arrow function without a body in braces;
  - a return type or type parameter written with braces;
  - an unbalanced brace inside a string, regex or comment in the body.
- `opro probe-fault`, `opro test-brief`, `opro verify-test` and `opro export-tests` now accept these functions. Before, they took only members written `owner.name = function` or `F.prototype.name = function`.
- One location format, `orangepro.location.v1` (`dist/local/contracts/location.d.ts`), names the exact place of every change, for the kit and for add-ons alike.

## `opro probe-fault` needs an approved expected behavior

- An expected behavior (`oracle.json`) whose `approval.status` is `proposed` is refused (`oracle_not_approved`) unless `--allow-proposed-oracle` is given.
- With the flag, the run profile records `oracle_status`, and the receipt carries the expected behavior's approval as it is.

## Clearer output

- A proof that cannot start prints one line with the cause, for example `The proof could not start: vitest runner binary not found: …`.
- "No linked test" replaces "No test points here". The pointer for a function with no linked test reads "No test calls it. Start with <file>: it imports this file" (or "…it matches this file's name"), so it no longer reads as a claim that the test runs the function.
- When test files send HTTP requests, the summary says "N of M test files send HTTP requests; the map doesn't trace those calls".
- `opro doctor --proof` heads a mutant run that hit its time limit "ran past the time limit", never "mutant survived".
- `opro rtm --status` takes the five evidence names, maps the old ones, and refuses an unknown name with the list of valid ones.
- The remaining sentences that used old tier words now use the README's names.
- The summary report's platform card sits right after the top functions, and the summary has the same one-line bar at the bottom as the detailed report.

## Commands and options

- Every command accepts `--flag=value` as well as `--flag value`.
- `--generate-limit 0` stops every drafted test, auto-prove's own drafting included.
- `opro generate` makes one suite. `--compare` adds the prompt-only suite and the judge, and says before it runs what `--limit` means in model calls. `--single` is still accepted and does nothing.

## Reliability

- Each `verify-test` stage runs on its own fresh copy, and a file a stage rewrote is hashed inside the container before the stage runs. A mismatch is "inconclusive".
- The signed test reporter signs nothing once a test has replaced `Function.prototype.call`, `Function.prototype.apply` or `Reflect.apply`. Newer Node versions (24.21 and later, 25) had let a forged pass through. CI now also runs these tests on Node 24 and 26.

## Optional add-on interface

- If the separate package `@orangepro/mcp-pro` is installed next to the kit, the kit can ask it for proposals at five points:
  - `FaultSelector`: which fault to try;
  - `OracleProposer`: a draft of the expected behavior;
  - `CheckResolver`: which existing test to try for a function;
  - `RuntimeLinker`: coverage files it produced;
  - `PlatformClient`: an upload of the run's files.
- An add-on only proposes. The kit checks every answer as it checks a person's input, and only the kit's own runs set an evidence tier or a result.
- **Without an add-on, nothing changes,** apart from `opro doctor` printing `pro add-on: not installed`.
- An add-on inside the repository being scanned is never loaded. `ORANGEPRO_PRO=off` turns an installed add-on off. Interface version 1.0.0 (`dist/local/pluginApi.d.ts`).

## Output shape changes, for tools that read OrangePro output

- **`report-data.json`:** `REPORT_DATA_VERSION` 5 → 6. `counts` gains `testFilesHttp`.
- **Proof oracle:** `orangepro.targeted_mutation_oracle.v5`. Attempts carry the reach outcome.
- **`.orangepro/model-usage.json`** (new): model, input and output tokens for each model call. Commands that call a model also return `model_usage` in their JSON result.
- **Target records** (`opro changed-targets`):
  - `mutation_route` is `bound`, `position` or `unsupported_shape`; `name_search` is gone.
  - A `position` record carries `declared_name`.
  - A record from an earlier version that says `name_search` is refused as stale.
- **New refusal codes:** `symbol_not_found`, `brace_in_signature`, `brace_in_string`, `name_mismatch`, `function_hash_mismatch`, `name_search_disabled`, `oracle_not_approved`.
- **Run profiles** may carry `oracle_status`, and, when an add-on's answer was used, the add-on's name and version.

## Requirements

Unchanged from 0.2.61: Node ^22.23.4, ^24.22.1 or >=26.12.1, on macOS or Linux. `probe-fault`, `verify-test`, `draft-test`, `export-tests` and `actions-run` run the repository's tests in a Docker container. `publish-tests` needs only Node and a GitHub token (`GITHUB_TOKEN` or `GH_TOKEN`).

## Dependencies

No dependency changes. `npm audit --omit=dev` finds 0.
