# 0.2.61

Everything since 0.2.60.

## In short

- **Patch status in the reports:** a function a finished proof run verified shows "Verified test patch (not merged)" next to its evidence, with links to the patch and the run's page. It is not an evidence tier: counts and verbs are unchanged.
- **New: `opro publish-tests`** delivers a verified test patch as one **draft** PR through the GitHub API. It runs no repository code and no git, and refuses when the code under the PR is not the code that was proven.
- **New, opt-in: `install-github-action --deliver draft-pr`** adds a separate deliver job, the only job with write permissions. The Actions artifact now holds both reports, re-rendered with the PR link after a delivery.
- **`summary.html`** names and links the repository, the merged commit and the source PR.
- **The one-page summary says what this run did,** and roughly how long it would take by hand. Both reports link to the OrangePro platform.
- **Packaging:** `CHANGELOG.md` and `SECURITY.md` now ship in the package, and the launcher's npm description fits npm's 255-character limit.
- **The first run after upgrading is a full run:** the report data format changed.

## Patch status in the reports

- A function that a finished `opro export-tests` run verified now shows a **patch status** next to its evidence label, in both reports: **Verified test patch (not merged)**, with links to the run's page and `orangepro-tests.patch`.
  - **Other values:** in this checkout; stale (the function or the test file changed since the proof); delivered as a draft PR; adopted (merged), only when a merge was read back from GitHub.
  - **Runs that claim nothing:** an inconclusive or blocked run says "no claim". A run whose folder does not verify is not used, and Run details says why.
- **It is not an evidence tier.** The five tier counts, Proven included, are unchanged. The row keeps its tier and its verb until the merged test is proven.
- The one-page summary adds one line beside Proven, for example "1 verified test patch, not merged".

## What this run did, and the platform link

- **"Done by this run"** on the one-page summary counts only what that `opro start` run produced:
  - tests OrangePro wrote whose run passed;
  - drafts that never ran (the drafted tests are compile-checked at most, never run);
  - functions proven in this run;
  - tests found in the repository whose mutant survived (never a time-out, a set-up failure or an inconclusive run).
- **"By hand, about X engineer-hours":** 10 minutes per test written and passing, 5 per draft, 5 per function proven, 15 per test that doesn't catch a break. The sources are printed under it.
- **A "Not counted" line** names what the run also did: mapping the functions to the test files and ranking them.
- **Zero items are hidden.** Reports written by any command other than `opro start` show only the "Not counted" line. Static-only runs count drafts only.
- **The platform link:**
  - the summary has a "From functions to workflows" card above the footer;
  - the detailed report has a one-line bar at the bottom of the screen ("OrangePro platform · See the platform → · Give feedback").
  - Both go to `https://orangepro.ai/` with `utm_source=mcp_report` and `utm_medium=summary` or `detailed`. Nothing is sent from the page.

## `summary.html`

- The page names the repository: the fork when the fixture names one, else the upstream. It had said "repository at …".
- It links the repository, the merged commit and the source PR on github.com.
- The approved expected behavior appears once. The checked value is in the new-test card.

## `opro publish-tests`: the draft-PR publisher (new)

- **What it does:** delivers one verified test patch as a **draft** PR, through the GitHub REST API. It runs no repository code and no git.
- **What it checks first:**
  - the run's manifest, the receipt (`verified_gap`, rows A–H), the patch (one test file, lines added only), the fixture's allowlist and the build;
  - that the base branch still points at the proven commit, or at it plus only OrangePro's installed files (below). If not: `stale_base`, nothing written.
- **Where it writes:** one commit on `orangepro/tests/<merged sha, 12>`, never force-pushed. A branch with someone else's commit is `diverged`.
- **Reruns** find the same PR. It reads the PR back and records what GitHub says in `delivery-record.json`.
- **Without `--yes`** it makes no request.

## Delivery against a base that only adds OrangePro's files

- `publish-tests` also delivers when the base branch is the proven commit plus only the files the installer owns: `.github/workflows/orangepro-proof.yml` and `.orangepro/actions/`. It reads this from GitHub's compare API.
- The code under the PR is then the code that was proven, and the PR says so.
- Any other change to the base is still `stale_base`.
- A rerun whose patched test file is byte-identical reuses the branch (no new commit) and refreshes the PR's description.

## GitHub Actions: an opt-in deliver job

- `opro install-github-action --deliver draft-pr` (or `deliver: "draft-pr"` in the MCP tool) adds a `deliver` job after `prove`.
  - It is the only job with write permissions.
  - It checks out nothing, and runs `publish-tests` on the run's own artifact.
- Without the option, the workflow is unchanged.
- **What `actions-run` writes:** both reports, `tests.csv` and `report-data.json`, beside the run folders.
- **After a delivery,** the deliver job re-renders both reports with the read-back PR as the row's patch status, and uploads them as `orangepro-report-<run>`.

## Output shape changes, for tools that read OrangePro output

- **`report-data.json`:** `REPORT_DATA_VERSION` 3 → 5.
  - It gains `byHand` (`run`: the four counts, the minutes and whether the run was static-only, or null on reports another command wrote; `notCounted`: functions and test files).
  - It gains an optional `patches` object (`line`, `counts`, `rows`, `ignored`), present only when there is a proof run.
  - Worklist rows may carry `patch` (`state`, `label`, `text`, `run`, `page`, `patch`, `pr`).
  - A run that finds an older file makes a full run.
- **`proof-attempts.json`:** each attempt may carry `test_source`, `"written"` (OrangePro wrote the test this run) or `"found"`. A record without it is read as found.
- **The reuse key** includes each finished proof run's manifest, so a new receipt makes the next run a full run.
- **`verification-receipt.json`:** `source.repository` is now filled from `origin.upstream` or `origin.fork` (it was null for the Express fixture).

## Packaging

- `@orangepro/orangepro-mcp` now ships `CHANGELOG.md` and `SECURITY.md`.
- The `@orangepro/mcp-server` npm description is shorter, within npm's 255-character limit. The 0.2.60 description was cut off.

## Requirements

Unchanged from 0.2.60: Node ^22.23.4, ^24.22.1 or >=26.12.1, on macOS or Linux. `probe-fault`, `verify-test`, `draft-test`, `export-tests` and `actions-run` run the repository's tests in a Docker container; `publish-tests` needs only Node and a GitHub token (`GITHUB_TOKEN` or `GH_TOKEN`).

## Dependencies

The repository's lockfile moves `hono` from 4.13.14 to 4.13.19, after five advisories published on 12 Nov (GHSA-4m76-xfj5-7975, GHSA-h7mg-cq63-vhpq, GHSA-3gg2-335m-rxc6, GHSA-46wx-v44x-9hh2, GHSA-4h7h-rv7c-7m2v). The local server never loads it: it comes with the MCP SDK's HTTP transport, and `opro mcp` uses stdio. The published package does not pin it, so a fresh install already resolves the fixed version. `npm audit --omit=dev` finds 0.
