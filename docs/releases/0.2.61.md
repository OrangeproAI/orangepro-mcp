# 0.2.61 (unreleased)

## Patch status in the reports

- A function that a finished `opro export-tests` run verified now shows a **patch status** next to its evidence label, in both reports: **Verified test patch (not merged)**, with links to the run's page and `orangepro-tests.patch`.
  - **Other values:** in this checkout; stale (the function or the test file changed since the proof); delivered as a draft PR; adopted (merged), only when a merge was read back from GitHub.
  - **Runs that claim nothing:** an inconclusive or blocked run says "no claim". A run whose folder does not verify is not used, and Run details says why.
- **It is not an evidence tier.** The five tier counts, Proven included, are unchanged. The row keeps its tier and its verb until the merged test is proven.
- The one-page summary adds one line beside Proven, for example "1 verified test patch, not merged".

## `summary.html`

- The page names the repository: the fork when the fixture names one, else the upstream. It had said "repository at …".
- It links the repository, the merged commit and the source PR on github.com.
- The approved expected behavior appears once. The checked value is in the new-test card.

## `opro publish-tests`: the draft-PR publisher (new)

- **What it does:** delivers one verified test patch as a **draft** PR, through the GitHub REST API. It runs no repository code and no git.
- **What it checks first:**
  - the run's manifest, the receipt (`verified_gap`, rows A–H), the patch (one test file, lines added only), the fixture's allowlist and the build;
  - that the base branch still points at the proven commit. If not: `stale_base`, nothing written.
- **Where it writes:** one commit on `orangepro/tests/<merged sha, 12>`, never force-pushed. A branch with someone else's commit is `diverged`.
- **Reruns** find the same PR. It reads the PR back and records what GitHub says in `delivery-record.json`.
- **Without `--yes`** it makes no request.

## GitHub Actions: an opt-in deliver job

- `opro install-github-action --deliver draft-pr` (or `deliver: "draft-pr"` in the MCP tool) adds a `deliver` job after `prove`.
  - It is the only job with write permissions.
  - It checks out nothing, and runs `publish-tests` on the run's own artifact.
- Without the option, the workflow is unchanged.

## Output shape changes, for tools that read OrangePro output

- **`report-data.json`:** `REPORT_DATA_VERSION` 3 → 4.
  - It gains an optional `patches` object (`line`, `counts`, `rows`, `ignored`), present only when there is a proof run.
  - Worklist rows may carry `patch` (`state`, `label`, `text`, `run`, `page`, `patch`, `pr`).
  - A run that finds an older file makes a full run.
- **The reuse key** includes each finished proof run's manifest, so a new receipt makes the next run a full run.
- **`verification-receipt.json`:** `source.repository` is now filled from `origin.upstream` or `origin.fork` (it was null for the Express fixture).
