# 0.2.45

## Python static Association
- Resolve class-method invocations through exact assignments, inline constructions, fixtures, setup methods, inheritance, and tightly guarded unique-method cases.
- Check exact receiver identifiers instead of a text-level escape heuristic; aliases, receiver escape and reassignment still refuse the link.
- Resolve finite, literal `request.getfixturevalue()` selections through locally declared pytest fixtures and apply their mocks before linking. Unknown, missing or non-literal selections still refuse the link.
- Scope target-mock suppression to the linked test and its statically selected fixtures, not every unrelated test in the file.
- Exclude patched, mocked, ambiguous, reassigned, escaped, or otherwise underivable receivers. Association requires a resolved test invocation; it is not dynamic proof or coverage.

## Python proof execution
- Select the Python test environment from the nearest bounded project root; prefer a prepared project environment, otherwise install locked dependencies without building local workspace packages.
- Before any baseline or mutation, confirm the target module imports from the isolated copy. Ambiguous module paths and external imports cannot earn proof.
- Preflight each project once and preserve command, cwd, exit, duration, failure class and a redacted tail when collection or the environment cannot start.
- Continue across candidates instead of letting red baselines in one project exhaust the proof budget. Select return-type-compatible mutation sentinels and fail closed when the return contract is ambiguous.
- Select tests by exact graph-linked path. Sidecar attempts count runner invocations, not deduplicated observations. Go, Java and TypeScript diagnostics are structured too, with no change to their proof verdict rules.

## Ranking and structural risk
- Incoming references no longer divide a module-wide import count equally among unrelated symbols.
- Python classes with analyzed methods, enum declarations, trivial constructors and safe thin external delegates stay in the graph and denominator but are excluded from the primary priority ranking. Exclusion codes are disclosed.
- Git churn uses a bounded recent-history scan and reports complete, partial or unavailable with the reason. Partial churn is file-level.
- A destructive sink behind exactly one in-repository constructor chain is retained; arbitrary factory chains are not.
- ORS formula and version are unchanged: `orangepro.ors.stable_population.v2`.
