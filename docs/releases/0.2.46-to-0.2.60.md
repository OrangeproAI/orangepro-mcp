# What changed from 0.2.46 to 0.2.60

This page is for anyone who ran OrangePro 0.2.45 or earlier and now compares results with a newer version. It says, in one place, which changes move the numbers and why, then lists each version. The full notes for 0.2.60 are in [0.2.60.md](0.2.60.md); the notes for 0.2.42 to 0.2.45 are next to it.

Published versions in this range: 0.2.46, 0.2.47, 0.2.48, 0.2.49, 0.2.50, 0.2.53 (which includes 0.2.51 and 0.2.52), 0.2.54, 0.2.56, 0.2.57, 0.2.58, 0.2.59 and 0.2.60. There is no 0.2.55.

## Changes that move results

Read these first if a number moved between two runs of the same commit.

### A file import is no longer a reference to every function in the file (0.2.45; first GitHub release 0.2.46)

- **Before:** a file's import count was shared equally among the counted functions in that file, used or not. A function that nothing called could still look central: in a file with only one counted function, it took every import.
- **Now:** only a call to the function, a named import of it (JavaScript, TypeScript and Python), or a `module.attribute` reference to it (Python) counts. Fewer incoming references means a lower impact score. As before, a function with no incoming reference that calls no other function in the repository is marked disconnected, and its score is cut to a quarter. A function whose references were all file imports now drops sharply.
- **Example:** in a public Playwright end-to-end repository, a page-object method lives in a file that 15 other page files import, and only the end-to-end specs call it. It was ranked first in 0.2.44 (score 160, 15 incoming references): it was the only counted function in its file, so it took all 15 imports. From 0.2.45 on it is 32nd of 106 in the full ranking that `opro gaps` returns (score 4, 0 references), measured on 0.2.45, 0.2.46, 0.2.54, 0.2.56, 0.2.58 and 0.2.59. The report's worklist shows at most three functions per file, so it sits higher there. In 0.2.60 it leaves the worklist as test support (see below).
- **When it came out:** this change shipped in 0.2.45, which was published to npm without a GitHub release (its notes are in [0.2.45.md](0.2.45.md)). The first GitHub release that includes it is v0.2.46.
- **What 0.2.46 added:**
  - The report splits a reference count into calls, named imports and `module.attribute` references when the count includes an import.
  - Entry points a framework calls are no longer marked disconnected: a registered CLI command, or an endpoint or job handler.
- **Still open:** calls from tests do not count as callers, so such a method can read "no callers" while tests call it.

### Name matches no longer depend on test folder names (0.2.56)

- **What a name match is:** a lead from a test file's path or its test names to a function or a flow, shown as **Unconfirmed**. It is never counted as a link.
- **The change:** these leads no longer depend on folder names such as `tests/unit` or `tests/test_<pkg>`, so moving tests between folders does not change them.
- **Example:** on the same repository, unconfirmed leads went from 84 (0.2.44 to 0.2.54) to 77 (0.2.56 on). The name-match leads among them went from 52 to 45; the other 32, from a test importing the file, did not change. The 8 that went each led from the flow of one spec file to a different spec file. One new lead appeared.
- **Not changed:** test links and proofs (8 test links in every version).

### Ranking inputs

- **Change history (0.2.46).** Change frequency now covers the whole 180-day window by default. The scan limit rose from 5,000 commits or 60 seconds to 20,000 commits or 300 seconds, so the window on an active repository is no longer cut short. Set `tuning.churn_max_commits` and `tuning.churn_timeout_seconds` to change the limits.
- **Ranking v3 (0.2.58).** Code that a coverage run executed now counts as detectable, like code a test calls. Repositories without a coverage file are not affected.
- **Less load-dependent ranking (0.2.58).** On large repositories, the check for new code could time out on a busy machine, so the ranking could vary with machine load. Its time limit rose from 4 to 60 seconds per batch, so this is now rare.

### What counts as deleting data

The "Deletes data" filter shows code paths that reach a delete. These no longer count:
- browser storage (`sessionStorage` and `localStorage.removeItem`, 0.2.46);
- deletes on a cache (0.2.56);
- deletes on a `Set` or `Map` held in a module-level JavaScript or TypeScript variable, such as `const seen = new Set()` (0.2.57).

A sink you name in `destructive_sinks` still counts for a cache or for browser storage. A delete on a module-level `Set` or `Map` is not recorded as a call, so naming it does not bring it back.

### More JavaScript and TypeScript is seen (0.2.59)

- **Newly seen:** `export { a, b }` lists, `Foo.prototype.x = function …`, methods assigned to an exported object (as Express does), `module.exports = { a, b }`, and an unnamed `export default function`.
- **What counts:** a newly seen function counts when it is public (an entry file hands it out, or its name or folder marks it as a handler, service or similar), its authors do not mark it private, and it does more than return or store a value unchanged or pass its own arguments straight to another counted function. Plumbing like that stays in the graph, uncounted. Functions 0.2.58 already counted do not change.
- **Effect:** totals grow on CommonJS libraries. Express goes from 1 counted function to 40.

### Test-support code leaves the worklist (0.2.60)

- **What changed:** a JavaScript or TypeScript file that is not a test file but imports a test framework is treated as test support. The frameworks are `@playwright/test`, `playwright/test`, `@jest/globals`, `vitest`, `cypress` and k6. Page objects and `test.extend` fixtures are the usual cases.
- **What stays the same:** these functions stay in the graph and in the total, and no other score or order moves.
- **Effect:** in a repository that is mostly end-to-end tests, the worklist and `tests.csv` can now be empty. Both reports then say why.

### Python links (0.2.48 and 0.2.49)

- More Python tests count as links:
  - a call whose result is stored once and asserted later, or a call that is the only statement inside `with pytest.raises` (0.2.48);
  - a call nested in an assertion, directly or through a builtin such as `len`, `list` or `isinstance` (not as an argument to another function); `raise f(...)` as the only statement inside `pytest.raises`; `from package import module` followed by `module.f()`; and one explicit re-export hop (0.2.49).
- No longer a link: a module-level function that the same test patches (0.2.48). The 0.2.49 rule for nested calls does not credit a call on the expected side of a comparison, such as `assert result[0] == 2 * f(x)`.
- 0.2.45 changed Python links too: see [0.2.45.md](0.2.45.md).

## Names: old and new (0.2.60)

0.2.60 uses the README's five evidence names as the evidence labels in `rtm.md` and its csv and json, `COVERAGE_REPORT.md`, the `opro start` and `opro rtm` summaries, `opro doctor`, the MCP tool text and the agent docs. A few sentences still use the old words, for example "runtime-covered" in the `opro start` coverage line. Labels only: no assignment, row or count changes.

| Before 0.2.60 | From 0.2.60 | `evidence_tier` key (unchanged) |
|---|---|---|
| Dynamically Proven (summary lines and the CLI; rows already said Proven) | Proven | `proven` |
| Runtime-covered | Runs under tests | `runtime` |
| Associated signal (the CLI said Statically Linked) | Linked | `associated` |
| Candidate signal (unconfirmed) | Unconfirmed | `candidate` |
| No integration signal | No test found | `none` |

- **If you parse `rtm.md`:** match the new names, or read the `evidence_tier` key from the csv or json output.
- **Filtering:** `opro rtm --status` takes the new names, the short keys (`proven`, `runtime`, `associated`, `candidate`, `none`) and the old row names. It does not take `Dynamically Proven` or `Statically Linked`: use `Proven` or `Linked`.

## Version by version

- **0.2.46:**
  - Fields-only Python data classes and trivial constructors no longer take ranking slots.
  - Plus the reference breakdown, the framework entry points, the change-history limits and browser storage above.
- **0.2.47 and 0.2.48:**
  - Proof sandboxes are always cleaned up.
  - A proof stops on a full disk or after repeated runner crashes, and skips `rank_exclude_paths`.
  - `--no-ai` never calls a model.
  - Saved drafts no longer include the provider's response.
  - Plus Python links (0.2.48).
- **0.2.49:** more Python links (above).
- **0.2.50:** every run also writes `short_behavior-coverage.html`, a one-page summary.
- **0.2.53:**
  - The summary shows what each proof replaced the function with, and names the proving test by path.
  - Python proofs work for namespace subpackages, and for functions that return nothing.
- **0.2.54:** in Python proofs, an `ERROR` line in the code's own output is no longer mistaken for a pytest error.
- **0.2.56:** cache deletes and name matches (above). The summary links each proof to its test line.
- **0.2.57:**
  - **No more usage data:** the anonymous scan ping is removed.
  - **Voluntary feedback links:** nothing is sent unless you submit the form. `opro feedback off` turns off the occasional question; `ORANGEPRO_FEEDBACK_URL=off` hides every link.
  - In-memory deletes (above).
  - Proofs run in repositories with more than one JavaScript test runner.
- **0.2.58:**
  - **New reports:**
    - Each ranked function gets one of four verbs: Done, Prove, Check or Write.
    - Two test slots for each of the top 20: two drafted tests when a model key is set, and a prompt to copy into your coding agent.
    - A `tests.csv` for TestRail, Xray or Zephyr.
  - Unchanged runs reuse their reports at once (`--fresh` runs in full).
  - Ranking v3 and the new-code time limit (above).
- **0.2.59:**
  - **Security:**
    - `.env` files are no longer read: keys come only from your shell or your MCP client's config.
    - The dependency advisories are fixed.
    - A proof no longer writes its mutation into your files when the source folder you pass is a symbolic link.
  - More JavaScript is seen (above).
  - Four commands take one changed function to a reviewable test patch: `probe-fault`, `test-brief`, `verify-test` and `export-tests`.
  - Builds are stamped, and a changed build is refused.
  - Node ^22.23.4, ^24.22.1 or >=26.12.1.
- **0.2.60:**
  - An opt-in post-merge GitHub Actions workflow, tested locally.
  - `opro draft-test`.
  - Signed test reports in `probe-fault`, `verify-test` and `export-tests`.
  - `--static-only`.
  - Test support by import (above).
  - One set of names (above).
  - Report counts that say what they count, and proof runs that say what happened, time-outs included.
  - The launcher pins its engine exactly.
  - `--proof-limit 0` means no proof attempt, and `--generate-limit 0` no drafted test slots.

## Comparing two runs across versions

- **Scores are not comparable across versions** when the analyzer or ranking identity changed. Both are recorded in `.orangepro/graph.json`, under `artifact_identity`:

  | Field | Value in 0.2.44 | Value in 0.2.60 |
  |---|---|---|
  | `analyzer_version` | `orangepro.analyzer.v3` | `orangepro.analyzer.v12` |
  | `ors_version` | `orangepro.ors.stable_population.v2` | `orangepro.ors.stable_population.v3` |
  | `oracle_version` | `orangepro.targeted_mutation_oracle.v1` | `orangepro.targeted_mutation_oracle.v4` |

- **To reproduce or compare runs:** pin both packages exactly, as [docs/reproducibility.md](../reproducibility.md) explains. From 0.2.60 on, pinning `@orangepro/mcp-server` pins the engine too.

## Still not counted

Linked numbers are a floor, not a coverage percentage. OrangePro does not link:
- tests that only assert on mocks;
- calls over HTTP or from end-to-end suites;
- in Python, objects reached only through a fixture;
- in JavaScript and TypeScript:
  - calls on an object a test gets from a fixture (for example Playwright's `test.extend`);
  - calls to an inherited method, which are not linked to the class that defines it.
