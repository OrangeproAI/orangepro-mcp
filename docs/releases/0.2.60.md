# 0.2.60 (unreleased)

## Test-support code leaves the worklist by what it imports

- A JavaScript or TypeScript file that is not a test file, and imports a test framework, is now treated as test support. The frameworks are `@playwright/test`, `playwright/test`, `@jest/globals`, `vitest`, `cypress`, and k6 (`k6` and any `k6/…` module, because k6 scripts are load tests). Page objects, `test.extend` fixtures and helpers built on them are the usual cases.
- Plain `playwright` does not count: product code can use the browser library. Subpaths such as `vitest/config` do not count either.
- Imports are read from the code itself. A framework name in a comment or a string never counts.
- What changes: these functions leave the primary worklist with the reason `test_support_helper`, as test support found by folder name (`fixtures/`, `mocks/`, `e2e-testing/` …) already did.
- What does not change: they stay in the graph, and they stay counted in the behavior total. They are taken out after scoring, so no other function's score or order moves. The score formula is unchanged (`orangepro.ors.stable_population.v3`).
- When test support is more than half of the counted functions, both reports show one line saying so, with the numbers. This is common in an end-to-end test repository whose application lives elsewhere.
- When nothing is left to rank, the one-page summary says why: the functions are test support, or none is ranked. It says every function is proven only when something was proven.

## tests.csv and the trace matrix agree on file-level links

- When a test file imports a function's file (or is named after it) but no test was traced calling the function, `rtm.md` already called it a Candidate, while `tests.csv` said "No test found". JavaScript and TypeScript rows now say `Candidate link only, not confirmed`, and name the test file to read first. The detailed report's row says the same.
- The verb stays Write, and the score, rank and evidence counts do not change. Go, Python and Java rows are unchanged for now.

## The launcher pins its engine exactly

- `@orangepro/mcp-server` now depends on `@orangepro/orangepro-mcp` at its own exact version, not a `^` range, so it always runs the engine it names. The release script keeps the pin exact.
- Every run records the launcher version next to the engine version (see below).

## One set of evidence names everywhere

- The trace matrix (`rtm.md`, and `opro rtm --format csv` and `--format json`), `COVERAGE_REPORT.md`, the `opro start` and `opro rtm` summaries, `opro doctor`, the MCP tool descriptions and the agent docs now use the README's five evidence names: **Proven**, **Runs under tests**, **Linked**, **Unconfirmed**, **No test found**. They replace "Dynamically Proven", "Runtime-covered", "Associated signal", "Candidate signal (unconfirmed)" and "No integration signal". "Reproven (this run)" and "Generated-unverifiable" stay. Both reports and `tests.csv` already used the five names.
- **For tools that parse `rtm.md`: the RTM status strings changed** (the Status column and the summary table). `opro rtm --status` still accepts the old names as well as the new ones (`associated` and `linked` select the same rows). The machine key `evidence_tier` (`proven`, `runtime`, `associated`, `candidate`, `none`) is unchanged.
- No tier assignment, row or count changes.

## The reports say what each number counts

- The one-page summary's "Delete data" card says it counts every ranked or proven function whose code reaches a delete, not only the top of the worklist. The worklist's "Deletes data" filter shows its share of that total ("68 of 126").
- "Left out" is split by the reason the analyzer recorded (generated; not near an API, route, command or job; utility, model and tooling code; types, constants and other declarations; trivial accessors; CI and test helpers), and a new line shows the subtraction: found − left out = counted, plus any requirements read from Markdown docs. Before, the functions left out as not near an entry point were labelled "types and constants".
- The worklist heading names the done rows that the "Everything" filter counts. The summary's Prove / Check / Write counts say "of the 20"; the sidebar says its counts are for the rows in the worklist.
- Dates are the run's local time, with the zone named ("3 Nov 2026, 21:31 local time (UTC−08:00)"). The zone is saved with the report data, so a re-render on another machine shows the same time and the same bytes.
- A previous report less than an hour old is "the run 10 minutes ago", not "the report of <date>".
- The Inputs card counts the test files that call a counted function and those that call none ("1,022 test files: 69 call a counted function, 953 call none that OrangePro traced").

## Proof runs say what actually happened

- A test whose run on the original code hit the time limit could not run: it is "needs setup" (category `timeout`), and the reason names the limit. It was filed as "does not protect" before. This holds in JavaScript/TypeScript, Go, Java and Python.
- A mutated run that hit the time limit is never Proven, and reads "ran past the time limit" in both reports and in `opro doctor --proof`, never "survived" or "does not protect". It was possible before for the JS/TS proof script to call such a run proven when the test had reported an assertion failure before the kill (the proof ledger refused it, but the attempt record said proven).
- A Go package that does not compile in the proof copy is called a compile failure, with the remedy (`go mod download`, or build the package once). "Sandbox setup gap" is said only when the sandbox itself could not start.
- With no model key, a run that tried the repository's own tests says proof ran and only drafting new tests was skipped. "Auto-prove skipped" is kept for runs where nothing ran.
- A run folder no longer fails its integrity check because macOS Finder or Windows Explorer added `.DS_Store`, `Thumbs.db` or `desktop.ini`. Any other file the manifest does not list is still refused.

## Output shape changes, for tools that read OrangePro output

- **`tests.csv`:** the columns are unchanged. Which functions get rows changes: test-support functions recognized by their imports no longer get rows. In a repository that is mostly end-to-end tests, the file can now hold only the header. For JS/TS rows with a file-level link only, "Evidence today" is `Candidate link only, not confirmed` (was `No test found`), and "What to do" is `Write: No test calls it. <test file> imports its file; read it first.` (or `is named after its file`), instead of `Write: No test points here.`
- **`report-data.json`:** `REPORT_DATA_VERSION` goes from 1 to 3. It gains `timeZone` (`offsetMinutes`, `label`: the zone the run happened in), `counts.testFilesLinked` and `counts.testFilesUnlinked`, worklist rows may carry `proofTimedOut`, and the "What was counted" card gains an `Arithmetic` row. It also gains an optional `testSupport` object (`count`, `counted`, `text`), present only when test support is most of the counted functions, and worklist rows gain an optional `fileLink` (the test file linked to the function's file). A run that finds an older file makes a full run instead of reusing it.
- **`graph.json`:** the analyzer identity is now `orangepro.analyzer.v12`, because more nodes carry `ranking_exclusion_reason_code: "test_support_helper"`. `artifact_identity` gains `launcher_version`: the `@orangepro/mcp-server` version that started the run, or `null` when the engine ran directly (`opro`). It is in no fingerprint, so comparisons between runs are unaffected. The identity schema stays `orangepro.artifact_identity.v1`.
- **`rtm.md`** (and the RTM csv and json): the status names change, see "One set of evidence names everywhere". Rows, order and tiers are unchanged. Test-support functions keep their rows and their status.
- **`opro start --json`:** `analyze.test_links` (`test_files`, `linked`, `none`). With no key and existing tests tried, `auto_prove.reason` is the new drafting message.
- **Proof records:** a mutated run stopped by the time limit has `mutant_status: "mutant_timed_out"`; a baseline stopped by it is classified `needs_setup` with category `timeout`. Each language's proof script reports the limit it used as `timeoutMs`.
