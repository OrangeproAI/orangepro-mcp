# OrangePro MCP 0.2.42 release notes

This release combines the validated Salesforce CLI analyzer recovery with two corrections found during the fixed-corpus Twenty CRM rerun.

## Evidence association

OrangePro now recognizes real default-exported and static `run()` command invocations used by oclif, Salesforce CLI, Commander, and matching `esmock` tests. On the fixed Twenty corpus, this moved 63 behaviors from Candidate to Associated. The increase is expected analyzer recovery, not repository drift.

> **Associated means a real invocation-backed test signal. It is not assertion-backed proof that the test detects a broken behavior. Only execution plus a targeted killed mutation earns Proven.**

The 25 newly Associated Twenty database-command methods were audited against the graph and matching source archive. Each has one hard `TESTED_BY` edge to the matching integration suite, an imported and constructed command, exact method invocation, and assertion-backed test context.

## ORS v2

ORS now normalizes Probability and Impact over the stable denominator-eligible production behavior population before evidence filters the priority worklist. An unchanged behavior therefore keeps the same score when an unrelated peer moves from Candidate to Associated.

The formula identity is `orangepro.ors.stable_population.v2`. Existing weights are unchanged.

## Ranking hygiene

Test-support helpers under paths such as `e2e-testing/`, `testing/`, `testutils/`, `testhelpers/`, `fixtures/`, `mocks/`, and `fakes/` remain in the graph and retain denominator eligibility. They are excluded only from the primary production priority ranking with reason code `test_support_helper`.

## Dependency lock

The production dependency lock was refreshed within existing manifest ranges. The release gate requires `npm audit --omit=dev` to report zero vulnerabilities. Development-tooling upgrades remain separate from this release.
