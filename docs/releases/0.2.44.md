# 0.2.44


## Python static Association

- Recognizes a narrow assigned-instance test pattern only when the test imports one production class, constructs one local instance, invokes one owner-qualified method exactly once, and directly compares the untransformed result in one assertion.
- Fails closed for local or ambiguous classes, mocks and fixtures, reassignment or aliasing, receiver escape, transformed results, assertion helpers, multiple calls, and ambiguous assertions.
- Static **Associated** remains an invocation-backed test link, not execution evidence. Only a targeted killed mutation can earn **Dynamically Proven**.

## Project-aware proof scheduling

- Orders proof candidates by hard evidence first, then dominant denominator language and bounded runner root, without changing ORS scores or evidence tiers.
- Recognizes package, Python, Go, Java, and Rust project roots, including pytest and tox configuration roots.
- Quarantines only narrowly classified setup failures within the affected runner root or Go package and preserves the shared proof budget for other runnable projects.
- Persists redacted scheduling and quarantine metadata in `proof-attempts.json` v2.

## Release safety

- Analyzer identity advances to `orangepro.analyzer.v3` because static Association semantics changed.
- Package versions remain aligned and require the normal typecheck, build, test, production-audit, package dry-run, and fleet gates before publication.
